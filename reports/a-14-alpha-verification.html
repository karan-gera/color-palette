Result

Observed: every behavior required for A-14 now has either repeatable automated coverage or a completed manual/native verification. No A-14 manual checks remain.

Decision boundary: this evidence supports the stated desktop-only public alpha. It does not certify offline startup, mobile UI, or the public-beta performance budget.

What we found and changed

surface before change observed after
transient status A status node mounted already populated. It appeared in the accessibility tree, but VoiceOver did not speak the update. Keep one empty polite live region mounted and change its text when a notification arrives; mark the visual duplicate hidden from assistive technology. pass — VoiceOver spoke “link copied to clipboard!”
fatal recovery The recovery view exposed role="alert", but VoiceOver initially announced only the web-content container. Make the recovery alert programmatically focusable and move initial focus to it after mount. pass — VoiceOver spoke “something went wrong alert”.
open / save dialogs Closing these controlled dialogs returned focus to the browser’s web-content root instead of the invoking control. Add a reusable hook that captures the active trigger before opening and restores it on close. pass — both dialogs returned focus to their triggers; the save dialog was announced as a named dialog.
preview overlays Palette and gradient previews lacked complete modal semantics and reusable focus containment/restoration. Add named modal-dialog semantics plus shared initial focus, Tab/Shift+Tab trapping, Escape handling, and trigger restoration. pass — both previews were announced as dialogs; repeated tabbing stayed contained and closing restored focus.
native eyedropper The browser/native picker could not be concluded from unit tests or simulated pointer input. Complete a native Helium screen-pixel selection against a known palette color. pass — the picked screen pixel produced the same hex as adding that color directly.
